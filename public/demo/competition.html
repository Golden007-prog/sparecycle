Meet SpareCycle Review

A laptop can be held back by broken software as well as broken hardware. SpareCycle Review connects what a team observes on the bench to a tested change in its project.

The company workspace

The company workspace brings laptop passports, project connections, and change requests together. Access follows organization membership, so a different company cannot read this team's records.

The laptop passport

This passport contains an observed parser failure, with its source and evidence revision. The records are synthetic. The failure, model calls, isolated tests, and published draft are real.

A clearly defined failure

Here, a valid zero-percent battery reading is incorrectly discarded as missing data. The request defines the expected behavior and preserves the existing tests before any code is proposed.

Nebius cloud inference

Nebius Token Factory is the cloud inference provider. NVIDIA Nemotron supplies the reasoning models.

NVIDIA Nemotron routing

In this completed change, Lightning investigated the evidence. Super generated the patch and independently reviewed it with fresh context.

Four-model usage evidence

The supplied Nebius usage screenshot records Nano, Lightning, Super, and Ultra. That confirms use across four model tiers, not that every tier wrote this patch. The displayed cost buckets are rounded.

The execution harness

Trusted code controls every transition. Structured output, a forty-second model deadline, and reserved spend constrain each stage. Exact code and evidence hashes, unchanged tests, stale-evidence rejection, and a separate approver protect publication. LangSmith traces contain metadata only.

The bounded patch

The proposed patch is restricted to the selected diagnostic parser and checked against the harness rules. It is bound to an exact repository version and evidence revision. Generating a patch does not make it approved.

Prove the failure and fix

An isolated GitHub Actions container first reproduces the failure: one test fails and three pass. With the candidate, all four unchanged tests pass. Hashes bind this result to the exact code and evidence.

Review the tested change

The independent review receives the original problem and evidence, without the writer's conversation. A different organization member must approve the tested change. New evidence or code invalidates that approval.

The real draft pull request

The SpareCycle GitHub App created this actual draft pull request with the tested patch and verification metadata. Technician narratives stay in the workspace. Repository review is still required, and publishing does not mark a laptop repaired.

The private-repository pilot

A separate private-repository pilot also completed: encrypted dispatch, one baseline failure, four unchanged tests passing, independent approval, and a real draft pull request. Synthetic QA accounts were used.

The recovery workflow

Review complements the recovery planner, connecting declared parts, workshop time, and repair budgets with a traceable software handoff.

What the demo proves

This controlled parser demonstration does not certify physical repairs. Enterprise email, private repository execution, and single sign-on each require separate verified configuration.
